# requirements-live.txt -- the live-edge workflow's packages, every one pinned.
#
# The runner installs from this file and nothing else (.github/workflows/
# live-edge.yml, live-edge-check.yml), with --require-hashes --no-deps
# --only-binary=:all:, so no package is compiled there, nothing unlisted is
# installed, and a file added to a pinned release after the fact is refused
# (D23, attack read finding 4). Each pin carries the sha256 of its wheels for
# CPython 3.14 on manylinux x86_64 and on win_amd64 (or its pure-Python wheel),
# read from PyPI's JSON API on 2026-10-08.
#
# The versions are what the Windows interpreter the freeze was built with
# carries (C:\Users\Ajayr\AppData\Local\Python\
# pythoncore-3.14-64, Python 3.14.6, through the project venv), so the runner
# rebuilds the pages from the same library versions the committed pages came
# from. A version rolling forward can change a page's bytes with no data
# change; the re-render check then fails the run, which is build-lane work.
#
# The closure is complete, not only the direct imports: duckdb (build_model,
# validate), numpy (forecast, build_page, pull_live_edge), statsmodels (the
# ETS candidate in forecast.fit_candidate) and what each of those requires.
# requests is not imported anywhere on the live path (acquire.py uses urllib)
# and is not listed. Proved complete by a clean venv without
# --system-site-packages (Build Brief 2.5 step 2).
#
# requirements.txt stays as it is: it names what the Windows venv adds on top
# of the system interpreter.
